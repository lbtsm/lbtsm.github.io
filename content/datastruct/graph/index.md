## Summary 

树结构已经是一个很强的结构了，但是它有一个硬性规定，就是每个只能拥有一个父节点，不能有环，然而现实里大量关系不满足这个约束——地铁线路图上两站之间有多条路径、社交网络里 A 关注 B、B 也关注 A、区块链的 P2P 网络里每个节点连着几十个 peer。图是数据结构的终极形态:它不要求连通、不要求无环、边可以有方向有权重。

只要你能定义清楚"什么是顶点、什么是边"。学会图,你手里就有了一把能刻画几乎任何关系型问题的通用刀。

## 图到底是什么

**图 G = (V, E)**:V 是**顶点(Vertex)** 的集合,E 是**边(Edge)** 的集合,每条边连接两个顶点。就这么简单,但配料很多:

- **有向 vs 无向**:边有没有方向。无向图里 `A—B` 表示互通(朋友关系);有向图里 `A→B` 不等于 `B→A`(关注关系、跨链桥的单向流动)。
- **带权 vs 无权**:边上有没有数值。带权边 `A—5—B` 表示距离/费用/汇率(地图、网络时延、DEX 汇率);无权就只关心"通不通"。
- **稀疏 vs 稠密**:边多还是少。顶点数 V,边数 E。E 接近 `V²` 叫**稠密图**,E 接近 V 叫**稀疏图**。现实里大多数图是稀疏的(你微信好友几百个,不可能几十亿)。这个区别直接决定下一节"用什么存"。
- **连通性**:无向图里任意两点都能互相到达叫**连通**;做不到就分成几个**连通分量(connected component)**。有向图里分**强连通**(互相可达)和**弱连通**(忽略方向后连通)。
- **环 / DAG**:有环就是从某点出发能绕回自己。**没有有向环的有向图叫 DAG(有向无环图)**——这是个极其重要的类别,依赖关系、构建顺序、区块 DAG、任务调度全靠它,拓扑排序就只对 DAG 成立。

```
无向无权:      有向带权:            DAG(有向无环):
  A —— B        A --5--> B           编译顺序
  |  / |        |        ^           main <- utils <- config
  | /  |        3        1                  ^
  C —— D        v        |                  |
                C --2--> D              main <- log
```

一个术语先记住:**度(degree)**。无向图里一个顶点的度 = 连着它的边数;有向图分**入度(in-degree,指进来的边数)** 和**出度(out-degree,指出去的边数)**。入度这个概念在拓扑排序里是主角。

## 两种表示法:邻接矩阵 vs 邻接表

图在内存里怎么存?

### 邻接矩阵(Adjacency Matrix)

用一个 `V×V` 的二维数组 `M`,`M[i][j]` 表示"从 i 到 j 有没有边"(带权就存权值,无边存 0 或 `∞`)。

```
   A B C D
A [0 1 1 0]     A—B、A—C 有边
B [1 0 0 1]     无向图矩阵沿对角线对称
C [1 0 0 1]
D [0 1 1 0]
```

- **优点**:查"i 和 j 之间有没有边"是 **O(1)**——直接下标访问。加边、删边也是 O(1)。
- **缺点**:空间 **O(V²)**,不管你实际有多少条边都得占满。V=10 万的稀疏图,矩阵要 100 亿个格子,根本存不下。遍历一个顶点的所有邻居也要扫一整行 O(V)。

**只适合稠密图,或者 V 很小、需要频繁查"两点间是否有边"的场景**(比如 Floyd 全源最短路、状态转移矩阵)。

### 2.2 邻接表(Adjacency List)

给每个顶点挂一个链表/切片,里面存它的邻居。这是**工程里的默认选择**。

```
A -> [B, C]
B -> [A, D]
C -> [A, D]
D -> [B, C]
```

Go 里两种写法。无权图直接 `map[int][]int` 或 `[][]int`:

```go
// 邻接表:顶点用 0..V-1 编号时,切片比 map 更快、更省
graph := make([][]int, V)
graph[0] = append(graph[0], 1) // 0 -> 1
graph[0] = append(graph[0], 2) // 0 -> 2

// 顶点是稀疏 ID(比如链地址哈希)时,用 map
g := map[int][]int{}
g[0] = append(g[0], 1)
```

带权图,给邻居配上权重,定义一个 `Edge`:

```go
type Edge struct {
    To     int
    Weight int
}
graph := make([][]Edge, V)
graph[0] = append(graph[0], Edge{To: 1, Weight: 5}) // 0 --5--> 1
```

- **优点**:空间 **O(V + E)**,只存实际存在的边,稀疏图省到飞起。遍历一个顶点的邻居只花 O(该点的度)。
- **缺点**:查"i 和 j 之间有没有边"要遍历 i 的邻居列表,O(度) 而不是 O(1)。

**取舍一句话记死:稠密图 / 频繁查边 → 邻接矩阵;稀疏图(绝大多数)→ 邻接表。** 。

> 一个过来人提醒:无向图加边要**加两次**(`u->v` 和 `v->u`),这是刚开始接触图时最容易忽略的地方。有向图只加一次。带权无向图两个方向的权重相同。

## 图的遍历:BFS 与 DFS

遍历图和遍历树,**唯一但致命的区别是:图有环,会绕回来**。

### BFS(广度优先,用队列)

```go
func bfs(start int, graph [][]int) []int {
    visited := make([]bool, len(graph)) // 标记是否已经已经遍历，防止绕回来
    var order []int
    queue := []int{start}
    visited[start] = true // 标记为true
    for len(queue) > 0 {
        node := queue[0]
        queue = queue[1:] // 出队
        order = append(order, node)
        for _, nb := range graph[node] {
            if !visited[nb] {
                visited[nb] = true       // 去重:标记后再入队
                queue = append(queue, nb)
            }
        }
    }
    return order
}
```

**一个必须点破的坑:标记时机。** 一定要在**入队的那一刻**就 `visited[nb]=true`,而不是等它出队时再标记。否则同一个节点会被多个邻居重复塞进队列,轻则变慢,重则爆内存。

因为 FIFO,BFS 天然按"距起点的层数"扩散,**无权图求最短路就用它**:第一次访问到某点时,走过的边数就是最短距离。

### DFS(深度优先,用栈/递归)

代码使用非递归的相对来讲容易理解一点，node从 stack[len(stack)-1] 开始遍历。

```go
func dfsIter(start int, graph [][]int) []int {
    visited := make([]bool, len(graph))
    var order []int
    stack := []int{start}
    for len(stack) > 0 {
        node := stack[len(stack)-1]
        stack = stack[:len(stack)-1] // 出栈
        if visited[node] {
            continue // 出栈时再判重,同一点可能被多次入栈
        }
        visited[node] = true
        order = append(order, node)
        for _, nb := range graph[node] {
            if !visited[nb] {
                stack = append(stack, nb)
            }
        }
    }
    return order
}
```

有个递归版的，就是有点绕，建议还是先写不递归的。递归的还是有点绕绕的。

```go
func dfs(node int, graph [][]int, visited []bool, order *[]int) {
    visited[node] = true
    *order = append(*order, node)
    for _, nb := range graph[node] {
        if !visited[nb] {
            dfs(nb, graph, visited, order)
        }
    }
}
```

测试时可以按照以下图进行测试：

```
0 ──── 1
│      │
2 ──── 3 ──── 4
```

在DFS中， 0,1,3,2,4 和 0,2,3,4,1 这两个顺序都是正确的，因为DFS只规定了一条路走到头，再回溯走其他的路，没有规定那条路要先走。想要相同顺序的话，非递归版可以把for循环，反着顺序写。

### 最短路径

无权图 BFS 就能求最短路,但**边一旦带权,BFS 就失效了**。原因很直白:**换乘两次的地铁,可能比直达一站的公交还快**——步数少不代表距离短。BFS 数的是步数,答不了这个问题。

带非负权的单源最短路,经典解法是 **Dijkstra**。

它的思路可以用水漫开来想象:从起点开始注水,水以相同速度沿所有管道流开。哪个点先被水淹到,哪个点的最短距离就先确定——因为水走的是最快的那条路,后面再怎么绕都不可能更快了。这个就很像以前网上一张很经典的图片，如下：

算法上的具体实现:维护一个"到各点的当前最短距离 `dist[]`",每次从**还没确定的点里挑 `dist` 最小的那个**拿出来"敲定"(它的最短距离不会再变了),然后用它去**松弛(relax)** 邻居。

"松弛"这个词听着抽象,意思其实很简单:**"绕道经过 u 走到 v,比我原先知道的路更近吗?近就更新。"** 反复松弛,直到所有点敲定。这个是不是就很像上一章我们讲的堆，用它来维护最短或者最长路径。

```go
import "container/heap"

type Item struct {
    node, dist int
}
type PQ []Item

func (p PQ) Len() int            { return len(p) }
func (p PQ) Less(i, j int) bool  { return p[i].dist < p[j].dist } // 小顶堆
func (p PQ) Swap(i, j int)       { p[i], p[j] = p[j], p[i] }
func (p *PQ) Push(x any)         { *p = append(*p, x.(Item)) }
func (p *PQ) Pop() any {
    old := *p
    n := len(old)
    it := old[n-1]
    *p = old[:n-1]
    return it
}

func dijkstra(start int, graph [][]Edge) []int {
    const INF = math.MaxInt
    dist := make([]int, len(graph))
    for i := range dist {
        dist[i] = INF
    }
    dist[start] = 0
    pq := &PQ{{node: start, dist: 0}}
    for pq.Len() > 0 {
        cur := heap.Pop(pq).(Item)
        if cur.dist > dist[cur.node] {
            continue // 过期的旧记录,跳过(懒删除)
        }
        for _, e := range graph[cur.node] {
            if nd := cur.dist + e.Weight; nd < dist[e.To] { // 松弛
                dist[e.To] = nd
                heap.Push(pq, Item{node: e.To, dist: nd})
            }
        }
    }
    return dist
}
```

此算法的时间复杂度 **O((V+E) log V)**(堆版本)。这个算法的基础是假设"敲定的点不会再变短"。但是负权边会打破这个假设。

### 其他应用

图还有很多用处，代码就留着给各位实现了，我力竭了。

1. 最短路 · Bellman-Ford(负权 + 检测负环)

Bellman-Ford 比 Dijkstra 慢,但更强:能处理负权边,还能检测负环（这条路反而更近、更方便）。

思想极其朴素:拿着图里所有的边,反复问"经过这条边,能不能让终点更近一点",能就更新距离。

这个就像是"你从家到全城每个地方最少花多少钱"。它的做法是:把城里所有的路,挨个问一遍——"绕这条路走,会不会更便宜?"会,就更新账本。问完一遍不算完,再从头问一遍,再问一遍…… 反复问上"路口数减一"遍,账本就再也不会变了,所有答案都是最优的。

妙的地方在于多问的最后那一遍。 按理说账本已经稳了,这时候你再问一圈,如果居然还有路能让账本变得更便宜——只有一种可能:城里有一个"绕一圈还能倒赚钱"的圈。因为只要有这么个圈,你就可以在里面无限转圈,越转越赚,账本永远稳不下来。

这个"绕一圈倒赚钱的圈",听着荒唐,但在一个地方真实存在——换汇。

套利:绕一圈,钱变多了

假设 1 美元换 7 人民币,1 人民币换 20 日元,140 日元换 1.05 美元。你拿 1 美元转一圈:美元→人民币→日元→美元,回来变成了 1.05 美元。什么都没干,凭空多了 5 分钱——这叫套利。银行和交易所最怕这个,套利机器人最爱这个。

2. 拓扑排序(只对 DAG)

这个问题你天天在遇到,只是没往图上想:排课表(高数得在微积分之后)、装修(水电改造得在铺地板之前)、编译(依赖的库得先编)、穿衣服(袜子得在鞋之前)。

共同点是:一堆事情之间有"必须先做谁"的依赖,要求排出一个线性顺序,让每件事都排在它依赖项之后。这就是拓扑排序。

前提是图必须是 DAG(有向无环图)。有环就无解——"A 依赖 B、B 依赖 A"这种死结永远排不出先后。

构建系统的编译顺序(Makefile、Bazel)、包管理器的依赖解析(go mod、npm)、任务调度、电子表格公式重算——全是拓扑排序。区块链里,交易依赖排序和区块 DAG 结构(见第 9 节)也用到它。

3. 最小生成树(MST)

场景:政府要给 10 个村子通电,村与村之间架线,每段线报价不同。要求:所有村子都通上,总花费最少。不难想清楚:最省的方案里绝不该有"圈"——一圈里去掉任何一段,大家照样通,还省一段的钱。所以最优方案一定是不多不少刚好把大家串起来,这个形状就叫最小生成树。

两个经典贪心算法,一句话记住区别:

- Prim:从点长树。 从一个点出发,每次挑一条"连接已选区域和外面、且最轻"的边,把新点纳进来,直到覆盖所有点。适合稠密图。
- Kruskal:按边挑树。 所有边按权重从小到大排,依次尝试:只要这条边不成环就要它,凑够 V-1 条边收工。适合稀疏图。

"这条边会不会成环"怎么判?看它两个端点是不是已经连通——已在同一块里,再连就是环。这个"判两点是否连通 + 合并两块"的操作,正是下一节并查集的看家本领,Kruskal 是它最经典的舞台。

4. 并查集(Union-Find)

并查集专门解决一类问题:动态维护"谁和谁在同一组",只有两个操作——Find(x):x 是哪一组的;Union(x, y):把两组合并。

理解它就用认老大:每个人只记"我的上级是谁",顺着上级一路往上问,问到那个"上级是自己"的人,他就是这伙的老大。判断两人是不是一伙,不用比对成员名单,看老大是不是同一个人就行。两伙合并也简单——让一个老大认另一个当老大。

落到实现上就是一个整型数组:每个元素记自己的"父亲",同组的最终都指向同一个根。它把"集合"这个看着很重的概念压成了一个数组,配上两个优化后,合并和查询都接近 O(1):

- 路径压缩:找根的路上,顺手把沿途每个人直接改成认根当上级——下次一步问到。
- 按秩合并:合并时让矮树挂到高树下,防止树越并越高、退化成链。
